# 规则缺口识别与扩展

本文件只在当前任务可能超出现有 `.agent` 规则时读取。新增或修改规则时以 `design-principles.md` 为设计基准。

## 判断缺口

先根据根目录 `AGENTS.md` 的路由项和 `.agent` 文件名判断，必要时只读取最可能相关的已有规则。现有规则能够合理覆盖时直接沿用，不创建同义、近义或仅粒度不同的新文件。

新扩展名、新工具或单次新任务本身不构成规则缺口。只有现有规则无法覆盖一组明确、非显然、今后可能重复使用的行为要求时，才视为长期缺口。

## 创建条件

同时满足以下条件时，可以创建新的 `.agent\<简短稳定主题>.md`：

- 使用方式已经扩展到新的长期工作流或职责；
- 至少能从真实任务提炼两到三条具体、可复用的规则；
- 规则不适合并入现有文件，也不与已有规则或 Skill 重复；
- 创建规则不会阻塞、扩大或改变当前任务目标。

证据不足、只是推测未来可能使用，或者只能写出泛泛建议时，不创建文件。

## 创建方式

- 文件名简短、稳定、含义清楚，避免同义词、缩写和大小写造成重复。
- 只写该职责特有的判断边界、默认行为、输出要求和必要验证，不复制通用规则或编写冗长教程。
- 在根目录 `AGENTS.md` 中只增加一条简短触发条件和链接，不改写无关规则。
- 先完成用户任务，再做不影响交付的规则补充，并在最终回复中说明原因和路径。
- 需要脚本、模板、素材、参考资料或完整专业流程时，优先创建或更新 Skill。

每个任务只做一次轻量缺口判断，不扫描整个工作区，不反复读取未变化规则，也不为一次性内容或假设场景创建文件。
