# 规则缺口识别与扩展

本文件只在当前任务可能超出现有 `.agent` 规则时读取。新增或修改规则时以 `design-principles.md` 为设计基准。

## 先判断是否真的存在缺口

1. 先根据根目录 `AGENTS.md` 的路由项和 `.agent` 文件名判断，必要时只读取最可能相关的已有规则；不要为了检查缺口而预读全部规则文件。
2. 现有规则能够合理覆盖时，直接沿用，不创建同义、近义或仅粒度不同的新规则文件。
3. 新文件扩展名、新工具或单次新任务本身不等于规则缺口。用户要求和通用常识已经足够完成时，正常完成任务即可。
4. 只有现有规则无法覆盖一组明确、非显然、今后可能重复使用的行为要求时，才视为长期规则缺口。

## 何时自动创建新规则

同时满足以下条件时，可以创建新的 `.agent\<简短稳定主题>.md`：

- 使用方式已经扩展到新的长期工作流或职责；
- 至少能从真实任务提炼两到三条具体、可复用的规则；
- 规则不适合并入现有文件，也不与已有规则或 Skill 重复；
- 创建规则不会阻塞、扩大或改变当前任务目标。

如果证据不足、只是推测以后可能会用到，或只能写出泛泛建议，则不要创建文件。先正常完成任务，等真实使用方式出现后再扩展。

## 创建方式

- 文件名使用简短、稳定、含义清楚的英文小写主题，避免同义词、缩写和大小写造成重复。
- 新规则只写该职责特有的判断边界、默认行为、输出要求和必要验证；不要复制通用规则，也不要写成长篇操作教程或穷举清单。
- 在根目录 `AGENTS.md` 中只增加一条简短触发条件和链接，不改写无关规则。
- 先完成用户任务，再做不影响交付的规则补充；最终回复中说明新建规则的原因和路径。
- 若新需求实质上是需要脚本、模板、素材、参考资料或专门流程的可复用能力，应优先创建或更新 Skill，而不是把整套流程塞进 `.agent`。

## 公开模板同步

- `AGENTS.md` 或 `.agent` 规则新增或变更后，如果存在对应的公开模板仓库，只比较本次涉及的对应文件，判断是否产生尚未同步的差异。
- 用户本次已经明确要求同步时，完成必要检查后直接同步；否则在本地规则完成后简短询问一次是否同步，不自动提交或推送。
- 用户选择暂不同步、没有回应，或当前额度、会员、网络和登录条件不允许时，保留本地修改并说明尚未同步，不反复追问，也不影响本地规则生效。
- 同步前继续执行隐私、许可证、个人路径和公开范围检查；私人参考原文及未纳入公开范围的规则不得因自动同步进入仓库。
- 同步成功后核对远程提交或页面状态；没有实际差异时不创建空提交，也不询问同步。

## 节省时间和额度

- 每次任务只做一次轻量缺口判断，不扫描全部工作区，不反复读取未变化的规则。
- 不为一次性内容、临时试验或仅一个文件创建专用规则。
- 不预先为尚未发生的假设场景建立规则；示例不等于真实需求。
- 新规则创建后，后续任务通过 `AGENTS.md` 路由按需读取，不默认加载全部规则。
