# 上下文连续性

本文件只用于保护长任务的可恢复状态。它不保存完整聊天记录，也不替代应用自身的对话历史。

## 何时启用

仅在出现以下任一情况时建立或更新恢复检查点：

- 界面提示上下文剩余不多，或已经发生上下文压缩；
- 多步骤任务持续较久，已经产生重要文件、决定或不可轻易重建的中间状态；
- 用户准备换对话，但要求以后继续同一项未完成工作；
- 当前任务在完成前可能中断，并且仅靠现有文件无法判断下一步。

普通聊天、短任务、尚未产生有效进展的任务，以及可直接从文件恢复的工作不创建检查点。不要为了判断是否需要保存而扫描全部聊天或工作区。

## 保存位置

- 具体项目：优先更新项目已有的状态文件，否则使用 `notes\continuity.md`。
- 非项目任务：使用 `<WORKSPACE_ROOT>\Chats\Continuity\YYYY-MM-DD-简短主题.md`。
- 同一任务更新同一份检查点，不按轮次重复创建。
- 用户指定保存位置时，以用户指定路径为准。

## 最小内容

只保留恢复工作必需的信息：

- 当前目标和完成标准；
- 已完成事项与已验证结果；
- 关键决定、约束和仍有效的假设；
- 重要文件的路径及其当前用途；
- 未完成事项、阻塞问题和下一步动作。

不要复制完整聊天、长篇工具输出、能够从文件直接读出的正文、无关讨论或已失效的尝试。不得把密码、令牌、密钥或其他敏感信息写入检查点。

## 更新与恢复

- 只在关键里程碑、状态发生实质变化或上下文即将压缩时更新；不要每次回复都写入。
- 写入前只核对当前任务涉及的文件；验证与风险相称，不运行额外的全量扫描或测试。
- 恢复任务时先读这份检查点，再按其中列出的路径读取仍然必要的少量文件；不要重新读取全部历史资料。
- 检查点与实际文件冲突时，以当前文件和用户最新要求为准，并修正检查点。
- 任务完成后将状态标记为“已完成”。除非用户要求，不删除历史检查点，也不把它转存为完整聊天记录。

## 与其他规则的关系

- 文件归档仍遵守 `file-routing.md`，项目笔记和普通聊天摘要仍遵守 `chat-notes.md`。
- 本规则只保存任务连续性，不改变已有输出路径、验证边界或规则自动演进机制。
- 若长期出现新的上下文管理需求，再按 `rule-evolution.md` 扩展；不要预先创建多个按模型、工具或文件类型区分的上下文规则。
