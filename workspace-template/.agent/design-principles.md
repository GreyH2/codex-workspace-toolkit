# 工作区规则设计基准

本文件用于新增规则、审计冲突或重构路由；日常任务不需要读取。

## 核心原则

- 根目录 `AGENTS.md` 是唯一、简短、稳定的入口，不另建重复总入口。
- 具体规则放入 `.agent` 并按职责路由。文件数量本身不是主要成本，被加载进上下文的内容才是成本。
- 工作区规则描述 Agent 在当前目录中的行为；需要脚本、模板、素材或复杂流程的专业能力应使用 Skill，两者不混放、不互相复制。
- 用户最新的明确要求和指定路径优先于默认规则。

## 渐进式读取

- 依据 `AGENTS.md` 的触发条件，只读取当前任务真正相关的规则。
- 任务确实横跨多类职责时可以读取多份规则，但不默认预读全部 `.agent` 文档。
- 未变化的规则不在同一任务中重复读取；不要求例行扫描整个工作区、磁盘或代码库。
- 没有专用规则时，依据用户要求和通用能力直接完成任务。

## 规则质量

- 规则描述适用条件、判断边界、默认行为、输出位置和必要验证，不编写机械的步骤清单。
- 绝对措辞只用于安全、用户明确要求或真正不变的约束。
- 不为每种语言、文件扩展名、工具或细分操作各建一份规则。
- 只有稳定、重复、职责明显不同，并且会改变 Agent 决策的真实需求才值得新增规则。
- 自动扩展不得顺便修改无关规则，也不得覆盖用户当前任务目标。

## 工作量与验证

- 明确目标、完成标准和停止条件，同时允许 Agent 选择高效路径。
- 验证与风险相称：优先检查受影响范围，只有变更范围、失败或证据需要时才扩大测试。
- 普通只读检查、常规本地编辑和已授权的可逆操作可以继续；删除、不可逆覆盖、凭据、外部发布、生产环境和系统关键位置保留必要边界。
- 优化不得以牺牲正确性、文件安全、必要验证或用户明确要求为代价。

## 网络与外部服务

- 本机操作与网络及外部服务分开路由。只读查询使用最小充分检索；核心事实已有可靠依据时停止。
- 搜索优先直接相关的权威或原始来源，区分来源事实、推断和不确定内容，并提供可访问链接。
- 发布、上传或发送前只检查实际交付范围，在本地完成可预先完成的准备，避免反复询问和工具切换。
- 用户授权只覆盖其明确目标；扩大公开范围、接收者、权限或外部副作用需要相应授权。
- 完成后以远程服务中的权威状态验证结果，失败时不通过关闭证书验证或其他宽泛安全降级绕过问题。
- 本地规则变更只在存在公开版差异时询问一次是否同步；没有明确授权不自动提交或推送，暂不同步不影响本地规则生效。

## 普通对话效率

- 普通问答先给核心结论，默认简洁，不重复问题、既有结论或无关背景。
- 能依据可靠上下文回答时不调用工具；需要核实时先做最小范围检查，有足够证据即停止。
- 不为改善措辞、增加非必要例子或重复确认同一事实而继续检索。
- 节省额度不能取代正确性、必要依据、安全边界和用户明确要求；复杂问题仍应给予充分回答。

## 文件、聊天与上下文

- 交付物按类型或项目归档；具体项目的文件尽量集中在项目内部。
- 原始聊天由应用管理，没有长期价值的短对话不创建本地文件。
- 只有可复用结论、完整分析、明确计划、决定或排障步骤才保存简洁摘要。
- 长任务只在关键里程碑、上下文明显紧张、已经压缩或准备跨对话继续时更新最小恢复检查点。
- 检查点不复制完整聊天，并且同一任务更新同一份文件。

## 停止条件

- 能够正确完成当前任务时，停止继续搜索或扩展规则。
- 新内容能够由现有职责覆盖时，不创建同义文件。
- 新规则没有明确复用价值时，不创建。
- 不为尚未发生的假设场景提前搭建规则体系。
